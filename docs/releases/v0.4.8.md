0.4.8 follows 0.4.6 with the Pi prerequisite fix below (issue #905). It also carries the 0.4.6 setup readiness fix (issue #904) for anyone upgrading from 0.4.2.

## What's new

### Failed `pi list` probe names its cause instead of reporting no subagents (issue #905)

- `gabo-runtime-pi` now decides present, genuinely missing, or probe failed from the worker's own `pi list` run. A probe the worker cannot run (missing `pi`, non-zero exit, timeout) reports the exact command, exit and stderr and stops with no install paragraph and no build, instead of wrongly claiming "no subagents" for an installed `npm:gentle-pi`.
- `gabo init` keeps refusing to build Pi agents when the check cannot run, but names the probe failure (`the subagent-package check could not run (pi list failed or timed out), so no package could be confirmed`) with the step `run pi list until it exits 0, then rerun gabo init`, and drops the install paragraph in that case.
- A genuine exit-0 run with neither marker still prints today's refusal, and a listed package still builds with no refusal.

## Upgrading

1. Install the CLI:
   ```
   go install github.com/testeos-z/gabo-ai/apps/cli/cmd/gabo@v0.4.8
   ```
2. Update the Claude Code and Codex plugins and the Pi package.
3. Run `gabo init` in each project.
4. Ask your agent to rebuild the agents of every engine in `runtimes.*`.
5. Run `gabo check` until it passes.

The Pi package is `@gabo-ai/pi@0.4.8`.
