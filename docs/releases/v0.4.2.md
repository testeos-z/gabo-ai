0.4.0 was prepared but never tagged, so 0.4.2 is the first release after 0.2.10. It ships everything in the [0.4.0 notes](v0.4.0.md) plus the changes below (intents 0027 to 0030).

## What's new

### Locks: deterministic hooks (intent 0028)
- `gabo check --pre-command` judges a shell call before it runs. It blocks a push to `main`, `master` or `dev`, force pushes, `git branch -D`, `git worktree remove --force` and wide `rm -rf` targets. A non-coder session is blocked only on a push to `main`.
- `gabo check --pre-write` judges each file write. A coder write to a path in `human_only_paths` is blocked, through a file tool or a shell write (redirects, `tee`, `sed -i`, `cp`, `mv`, `rm`). A target the guard cannot read, such as a variable, `~`, a command substitution or a `cd` it cannot follow, is blocked for a coder.
- A coder edit to an existing test file is allowed with a warning.
- New `locks.*` keys set each lock to `block`, `ask`, `warn` or `off`. Every blocked, warned or asked call appends one outcome record, and the wave trace and report carry those records and the `not run` lines.
- The release gate checks tags, publishes, GitHub releases and merges into `main`.
- Relays send each engine's shell and file calls to the locks: the Claude Code plugin, the Codex plugin (`apply_patch` and shell), the OpenCode plugin and the Pi package.
- `gabo init` writes a base credential deny list for each engine: reads and edits of `.env`, `*.pem`, `*.key`, `secrets/`, `~/.ssh` and other credential paths. Pi has no native deny format and reports `not run`.

### Branch protection (intent 0029)
- `repo.protection.required_approvals` sets the approvals per branch.
- The `repository_host` contract has a protect-branches operation, and setup offers branch protection after the host slot is verified.

### Agent evals (intent 0030)
- New `eval.*` keys hold the eval set's counts, pass threshold and caps, with validation and a `gabo check` report.
- The `gabo-eval-runner` skill proposes the eval set and its baseline, runs accepted tasks in scratch copies, writes a run report against the baseline and the pass threshold, and pauses at its caps.
- A PR that changes agent configuration runs the eval set. A run below the threshold posts a notice on the PR, and the reviewer holds the automatic merge of that head.

### Coders and the reviewer (intent 0027)
- Coders follow the gentle-ai ODD and RDD rules. They return a report contract with RED/GREEN evidence, the checks with their exit lines, a fresh-context verifier and the RDD outcome.
- The cycle applies a done gate and a report gate, and writes the RDD, ODD and gate lines of every task to the wave trace. It records incidents and applies the two-times rule.
- The reviewer reads the review policy (`REVIEW.md`) and its rule sources from `dev`. It runs three tagged passes and blocks only on Important findings, with at most five nits. Its comment is ordered verdict, checks, then code read.
- Product QA runs the done contract on a scratch build.
- The reviewer flags an existing test that a PR loosens without a stated reason.

## Upgrading

Install the CLI before you install the plugins or the Pi package. The relays call `gabo check --pre-command`, which 0.2.10 does not have, so a relay paired with an older CLI blocks every shell call in a gabo project. The 0.2.10 CLI also rejects the `eval` key in `gabo.yaml`.

1. Install the CLI:
   ```
   go install github.com/testeos-z/gabo-ai/apps/cli/cmd/gabo@v0.4.2
   ```
2. Update the Claude Code and Codex plugins and the Pi package.
3. Run `gabo init` in each project. It writes the reviewer, the catalog, the engine hooks and the credential deny list of this release.
4. Ask your agent to rebuild the agents of every engine in `runtimes.*`.
5. Run `gabo check` until it passes.

The Pi package is `@gabo-ai/pi@0.4.2`.
