Evidence base (checked 2026-11-06 on `dev` at de617c2, against the engines' own documentation, and against the gabo-reviewer findings on cappy-lab/vulcam PR #638):

- **Nothing sets the main session.** No runtime skill (`gabo-runtime-claude`, `-codex`, `-opencode`, `-pi`, `gabo-runtime-builder`) or `gabo-setup` names `CLAUDE.md` or `AGENTS.md`, writes a main-session instruction or picks a default agent; `gabo check` reads none of it.
- **The assistant skill is not reachable by name** (vulcam PR #638, finding 1). `gabo-assistant` sits only at `.gabo/skills/gabo-assistant/SKILL.md`. Each runtime skill links into its skill directory only the skills some spec agent lists (`gabo-runtime-claude` build step 2, `gabo-runtime-codex` step 2, `gabo-runtime-opencode` step 2, `gabo-runtime-pi` "Links"), and the assistant runs as `main-session` with no agent file (`gabo-agent-templates/agents.yaml`, header comment and `launched_by`), so no engine gets a `gabo-assistant` link. This repository's `.claude/skills/` confirms it.
- **Project instruction files reach every session** (finding 2). The project `CLAUDE.md`, `.claude/CLAUDE.md` or `AGENTS.md` loads in every engine process started in the repository or a worktree: coder sessions started by `gabo-agent-host-local` (`claude --print --agent <role agent>` or `pi --print`, which still load project context files) and the Codex reviewer (`codex exec … -C <head checkout>`). A "you are the assistant" rule there contradicts the coder and reviewer role prompts and `gabo-assistant`'s own rule that it runs only in the owner's main session. The Claude reviewer runs with `--setting-sources user` and the Pi and OpenCode reviewers load no project files (`gabo-reviewer/SKILL.md`, `scripts/review-head.sh`).
- **No owner for a hand-written block** (finding 3): a block copied by hand with the `runtimes.assistant` value goes stale when the runtime changes.
- **Claude Code** (2.1.319; https://code.claude.com/docs/en/sub-agents): `claude --agent <name>` runs the main thread as that subagent; "To make it the default for every session in a project, set `agent` in `.claude/settings.json`"; "The CLI flag overrides the setting if both are present." A non-empty agent prompt replaces the default system prompt; CLAUDE.md still loads. The docs do not say whether the agent's `skills` preload in this mode. Claude Code reads `AGENTS.md` only when no `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` exists (https://code.claude.com/docs/en/memory.md), so a new `CLAUDE.md` would hide an existing `AGENTS.md`. It discovers skills only in `.claude/skills` (project, nested, `--add-dir`) and plugins, with no setting to read `.agents/skills` (https://code.claude.com/docs/en/skills.md); so Claude Code keeps its own `.claude/skills` links straight to `.gabo/skills`, never chained through `.agents/skills` (owner decision 2026-11-06, verbatim: "ok carpeta aparte").
- **OpenCode** (v2.0.32; https://opencode.ai/docs/config, /docs/agents): `default_agent` "determines which agent is used when none is explicitly specified"; it "must be a primary agent"; it "applies across all interfaces: TUI, CLI (`opencode run`), desktop app, and GitHub Action". Project agents are `.opencode/agents/<name>.md` with `mode: primary`. `--agent` picks another one.
- **Codex** (codex-cli 0.163.0; https://learn.chatgpt.com/docs/agent-configuration/subagents, /agents-md, /config-file/config-reference): custom agents are only spawned as subagents; no documented key selects a project's main-session agent. `developer_instructions` and `model_instructions_file` in `config.toml`, and `AGENTS.override.md` / `AGENTS.md` (Git root down, one per directory, 32 KiB default cap), all apply to every session in the project, `codex exec` included.
- **Pi** (1.4.0, `@earendil-works/pi-coding-agent` `docs/configuration.md`, `pi --help`): no project default-agent setting. `.pi/SYSTEM.md`, `.pi/APPEND_SYSTEM.md` and the context files `AGENTS.override.md`, `AGENTS.md`, `CLAUDE.md` apply to every Pi process in the project; `--append-system-prompt` and `--no-context-files` are per-launch flags only.
- In this repository `runtimes.assistant` is `claude`; `.claude/`, `CLAUDE.md`, `AGENTS.md` and `gabo.yaml` are `review.human_only_paths`.

## 2. Design

Each engine gets one main-session entry, chosen by what the engine supports: a project default agent where the engine has one (Claude Code, OpenCode), so the role never reaches other sessions; otherwise a block scoped to the owner's interactive session (Codex, Pi). The runtime skills own the entry, rebuild it from `gabo.yaml` and remove it from the other engines; `gabo check` verifies the same declaration.
