Plan items the spec left to `gabo-dev-lead`, answered here:

- **Entry table and templates (D4)**: **Proposed (auto)** `gabo-agent-templates/agents.yaml` gets a top-level `main_session` entry (`id: gabo-assistant`, `role`, `skills: [gabo-assistant]`, `template: agents/gabo-assistant.md`, `block: agents/gabo-assistant-block.md`), outside `agents:`, so `agentspec` keeps returning only the spec agents and `gabo check` never counts the assistant as a missing or extra agent; `gabo-agent-templates/SKILL.md` holds the table of each engine's entry (link, agent file and key, or block and file order). Reason: one table every runtime skill reads to remove stale entries (S4).
- **Check metadata (D5)**: **Proposed (auto)** a `metadata.main_session` map in each runtime skill: `kind: agent` with `config` (the project config files in resolution order) and `key` (the JSON key), or `kind: block` with `files` (the instructions files in resolution order). Values: Claude Code `kind: agent`, `config: [.claude/settings.json]`, `key: agent`; OpenCode `kind: agent`, `config` the files `gabo-runtime-opencode` already resolves (`opencode.json`, `opencode.jsonc`, `.opencode/opencode.json`, `.opencode/opencode.jsonc`), `key: default_agent`; Codex `kind: block`, `files: [AGENTS.override.md, AGENTS.md]`; Pi `kind: block`, `files` in the order T5 confirms (spec: `AGENTS.override.md`, `AGENTS.md`, `CLAUDE.md`). The agent file of `kind: agent` is `<agent_dir>/gabo-assistant.<ext>`. Reason: same pattern as `agent_dir` and intent 0008 D1, no engine name in Go.
- **D2 (Claude Code prompt)** and **D6 (Pi file order)** are fixed by the probes T2 and T5 before the tasks that use them.
- **Version bump**: not in this plan, on the coordinator's instruction of 2026-11-06; see Open questions 1.

## Steps

1. The entry table, the `main_session` entry, the assistant agent template and the scoped block text in `gabo-agent-templates` (T1). Delivers the S2 and S3 content and S4's one table (D4).
2. Probes: does a Claude Code main-session agent preload its `skills` (T2, D2); Pi's instructions file order (T5, D6).
3. One runtime skill per engine writes its entry when its engine is `runtimes.assistant`, refreshes it on every build and removes every other engine's gabo entry: Claude Code agent file, link and `agent` key (T3); OpenCode agent file, link and `default_agent` (T4); Codex scoped block and link (T6); Pi scoped block and link (T7). Delivers S1, S2, S3, S4.
4. `gabo check` verifies the entry against `gabo.yaml`, from the runtime skills' `metadata.main_session` (T8). Delivers S5.
5. `gabo-setup` rebuilds after changing `runtimes.assistant`; `gabo-runtime-builder` teaches `metadata.main_session`; the `gabo-assistant` Activation Contract names the entry (T9). Delivers S4's setup half and part of S7.
6. TRD 9.4, TRD 8.1 and the user docs describe the entry per engine (T10). Delivers S7.
7. The owner commits gabo-ai's own Claude Code entry locally; `gabo check` exits 0 (T11). Delivers S6.
