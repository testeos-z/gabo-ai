Key engine facts this design rests on:

| fact | source |
|---|---|
| Project agents are Markdown files in `.opencode/agents/`; the file name is the agent name; `description` is required; `mode` is `primary`, `subagent` or `all` (default `all`); `permission` replaces the deprecated `tools`; `hidden` hides a subagent from `@` but the model can still launch it. | docs/agents |
| Unknown agent options "are passed through directly to the provider as model options". | docs/agents |
| Skills are found in `.opencode/skills`, `.claude/skills`, `.agents/skills` (project, walking up to the git worktree) and in `~/.config/opencode/skills`, `~/.claude/skills`, `~/.agents/skills`; `name` must match the folder name and `^[a-z0-9]+(-[a-z0-9]+)*$`; unknown frontmatter is ignored; skills load on demand through the `skill` tool; there is no per-agent preload field. | docs/skills |
| Skills are keyed by id, a later source replacing an earlier one with the same id; a file that fails validation is logged as `skill file skipped`; each skill file is resolved with `realPath`. | binary |
| `OPENCODE_DISABLE_CLAUDE_CODE` or `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS` turns off `.claude` skill discovery (undocumented). | binary |
| v2 renamed tools: `bash` is `shell`, `task` is `subagent` (takes `agent` and `sessionID`), `apply_patch` is `patch`; `read`, `edit`, `write` take `path`; `skill` takes `id`; `todowrite` is gone. | binary |
| The `shell` tool takes `workdir` ("Working directory to execute the command in"); the `subagent` tool takes no directory. | binary |
| v2 has a native `opencode.session_move` tool ("make the worktree the session's working directory") and `worktree_create`. | binary |
| Nested subagents are limited by `experimental.subagent_depth`, "Defaults to 1"; beyond it the call fails with `Subagent depth limit reached`. The owner's config sets a top-level `subagent_depth: 2`, which this code path does not read. | binary, `~/.config/opencode/opencode.json` |
| Permission keys include `read`, `edit` (covers edit, write, patch), `glob`, `grep`, `bash`, `task`, `skill`, `webfetch`, `websearch`, `external_directory`, `doom_loop`; `external_directory` and `doom_loop` default to `ask`; last matching rule wins; agent rules merge over global rules; `--auto` approves asks but keeps explicit denies. v2 emits permission actions named `shell` and `subagent`. | docs/permissions, binary |
| Local plugins are JS or TS files in `.opencode/plugins/` (project) or `~/.config/opencode/plugins/` (global), loaded at startup; `tool.execute.before(input, output)` blocks a call by throwing; dependencies need a `package.json` that OpenCode installs with `bun install`. | docs/plugins |
| gentle-ai already manages, in `~/.config/opencode`: `default_agent: gentle-orchestrator`, global subagents (`gentle-ai-*`, `review-*`, `jd-*`, `test-*`), a global `edit: {"*": "ask", …}` rule, and the `opencode-review-transport.ts` plugin, which relays only the agents `review-risk`, `review-resilience`, `review-readability`, `review-reliability`, `review-refuter`, `review-validator`. | `~/.config/opencode` |
| `gabo check` reads `metadata.agent_dir`, `skill_dir` and `reviewer_link` of `gabo-runtime-<rt>/SKILL.md` from `.gabo/skills/` then `.gabo/runtimes/`; it looks for `<id>.<ext>` directly in `agent_dir`, matches `gabo-version:` anywhere in the file (frontmatter or comment), and checks each `skill_dir` once even when two runtimes share it. | `check/links.go`, `check/usecase.go` |
| `gabo.yaml` accepts only `claude` or `pi` for `runtimes.*` (config.go line 192, schema enum `["claude", "pi", null]`); the reviewer scripts accept only `REVIEWER_ENGINE` `claude` or `pi`. | `config/config.go`, schema, `gabo-reviewer/scripts/common.sh` |

## 2. Design

The change adds one catalog skill, `gabo-runtime-opencode`, that turns the neutral agent spec and templates into OpenCode files, and the small Go and schema changes that let `gabo.yaml` name the runtime. Nothing else in Go changes: `gabo check` already reads `agent_dir`, `skill_dir` and `reviewer_link` from any runtime skill. Build flow: prerequisites (S8) → links in `.opencode/skills` (S5) → probe agent → spec agents in `.opencode/agents` (S3, S4) → optional stage-gate plugin (S10) → `gabo check`.

Tool Map (D3), written as the permission keys an OpenCode agent can deny:

| capability | OpenCode v2 tools | permission keys denied when the spec lacks the capability |
|---|---|---|
| `read` | `read` | `read` |
| `search` | `grep`, `glob` | `grep`, `glob` |
| `edit` | `edit`, `write`, `patch` | `edit` |
| `shell`, `git`, `tracker`, `repository-host` | `shell` | `bash` (and `shell`, if S13 step 10 shows v2 does not alias it) |
| `memory` | MCP tools `<server>_*` of the memory adapter's server (for example `engram_*`) | `<server>_*` |
| `web` | `webfetch`, `websearch` | `webfetch`, `websearch` |
| `skills` | `skill` | `skill` |
| `subagents` | `subagent` | `task` (and `subagent`, as for `shell`) |

Slot fills: `{{methodology}}` is `gabo-methodology`; `{{adapter:<slot>}}` is `gabo-<slot>` with `_` written `-`; `{{reviewer_script}}` is `${XDG_DATA_HOME:-$HOME/.local/share}/gabo/skills/gabo-reviewer/scripts/reviewer.sh`, written literally so the shell expands it and the committed file holds no personal path.
