- **Go shape of `runtimes.assistant` (S1, D1)**: **Proposed (auto)** a list type that decodes a scalar or a sequence; `runtimes.coder` and `runtimes.reviewer` keep one `Runtime` with the extra value `session`. Callers keep single-value behaviour until T2, T3 and T4 switch them to the list; nothing ships between those PRs (all land in 0.2.10). Reason: smallest change that keeps every 0.2.10 fixture byte-identical.
- **Missing `{{engine}}` line (S6)**: **Proposed (auto)** an agent file with no engine line passes; only a filled value that differs from its agent directory fails. Reason: spec S5 and S1 require byte-identical `gabo check` output on the 0.2.10 fixtures, which carry no engine line; the version line already forces a rebuild on each release, which writes the slot.
- **`REVIEWER_ENGINE` under `session` (S11, D5)**: **Proposed (auto)** `REVIEWER_ENGINE` keeps standing in for `runtimes.reviewer` exactly as today (`common.sh` line 442); the engine argument is accepted only when that resolved value is `session`. Reason: one precedence rule; a user-level fixed engine closes the argument the same way a fixed `runtimes.reviewer` does.
- **Review request under `session` (S7, S11)**: **Proposed (auto)** the coder adds `engine <engine>` (its `{{engine}}`) to the placement request only when `runtimes.reviewer` is `session`. Reason: the coder is the agent that requests the review (`gabo-coder`), and S11 refuses the argument under a fixed reviewer.

## Steps

1. `gabo.yaml` accepts `runtimes.assistant` as one engine or a list and `runtimes.coder` and `runtimes.reviewer` as one engine or `session`, in the schema and in `config.Validate`, with the refusals (T1). Delivers S1, D1; `gabo check` update: config refusal lines.
2. One engine set (S2) in `gabo init`, `gabo check` and the reviewer scripts' `declared_agent_dirs`, pinned by one fixture table (T2). Delivers S2, D2, S5 (engine rules on the set); `gabo check` update.
3. `gabo init` writes the main-session key of every listed engine and removes it only from an unlisted full-tier engine (T3). Delivers S3, D7.
4. `gabo check` checks the main-session entry of every listed engine and names the list in the stale line; help text (T4). Delivers S5; `gabo check` update.
5. The `{{engine}}` template slot, the Main-Session Entry rules for a list in `gabo-agent-templates`, and the `built for` rule in `gabo check` (T5). Delivers S6, D3, S4 (templates); `gabo check` update.
6. The runtime skills build the entry for every listed engine, remove it only for an unlisted one, and fill `{{engine}}`: Claude Code and OpenCode (T6); Codex, Pi and `gabo-runtime-builder` (T7). Delivers S4, S6. Each refreshes its `plugins/codex/skills/` copy.
7. The reviewer scripts accept the `engine` argument only under `session` and only for a listed engine, with explicit refusal tests (T12); then `gabo-reviewer-placement-local` and the `reviewer_placement` contract accept and pass it (T16). Delivers S11, D5. This is the reviewer's security boundary: the scripts change has its own task.
8. `gabo-cycle` runs the wave on its session engine and resolves the review engine; the coder sends `engine` under `session`; the wave report names the engine (T8). Delivers S7, S11 (request side). Planned for open questions 2 and 3 as proposed.
9. A wave claims its intent through the `tasks` operations on the intent issue; the assistant picks only unclaimed intents and reports holders (T9). Delivers S8, D4, S12 (assistant). Planned for open question 1 as proposed.
10. Each wave keeps its own ledger lines with the session id and its worktrees under `<repo-name>-worktrees/<wave>/` and cleans only those (T10). Delivers S9, D6.
11. The agent hosts resolve `session` and lists (T11). Delivers S10.
12. `gabo-setup` offers the list and `session`; `gabo-reviewer-config` runs the isolation test for each listed `codex` or `opencode` engine under `session` (T13). Delivers S12, S11 (configuration).
13. The user docs describe the shapes and the coordination (T14). Delivers S14, S5 (docs).
14. Probes P1 and P2 on a disposable repository; results recorded on the issue, in this plan and in the closing PR (T15). Delivers S13.
15. The shared main-session block names the Codex and Pi engine in one fixed line, and the assistant resolves its engine from it; runs after step 9 and before steps 13 and 14 (T17). Delivers S16, D8.
16. `gabo-runtime-pi` lists the Engram memory tools explicitly in every Pi agent with `memory` and declares the tools each capability requires (T18). Delivers S17, D11.
17. `gabo check` fails a built agent that lacks a tool its runtime skill requires (T19). Delivers S17, D11; `gabo check` update.
18. The assistant's session start treats an unreadable global user file as unreadable, not missing, and the Pi permission is documented (T20). Delivers S19, D13.
19. A wave from a Pi main session runs the cycle in that session and launches coders as first-level subagents, per spec D12 A, owner 2026-11-07 (T21). Delivers S18, D12.
20. A Pi coder validates its review request like the `gabo-reviewer` relay and runs the user-level reviewer script itself through `bash`; Pi agent files list no `subagent_*` tool and `gabo check` fails one that does (T22). Delivers S20, D14, D15; `gabo check` update.
21. After T18 to T22 merge, probe P2a is rerun (T15, owner 2026-11-07).
