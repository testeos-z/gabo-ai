Plan items the spec left to `gabo-dev-lead`, answered here:

- **Metadata keys (D1)**: **Proposed (auto)** two optional keys in a runtime skill's frontmatter `metadata`: `agent_skills` and `agent_name`, each a `<form>:<argument>` string. Forms: `frontmatter:<key>` (a YAML list or scalar under that key of the file's frontmatter), `toml:<key>` (a top-level TOML string key), `line:<prefix>` (the first line whose trimmed text starts with `<prefix>`, also inside a TOML multi-line string; the skill list is the text after ` for each of ` when present, else after `<prefix>`, without the final `.`, split on `,` and trimmed). Values: `gabo-runtime-claude` `agent_skills: frontmatter:skills`, `agent_name: frontmatter:name`; `gabo-runtime-codex` `agent_skills: "line:Load these skills by name before work:"`, `agent_name: toml:name`; `gabo-runtime-opencode` `agent_skills: "line:Skills:"` and no `agent_name` (OpenCode names an agent by its file name, so S6 does not apply); `gabo-runtime-pi` `agent_skills: "line:Skills:"`, `agent_name: frontmatter:name`. Reason: the forms read today's agent files unchanged, and an agent file with no matching place yields an empty list, which S1 then reports skill by skill.
- **Former skill directory (S4)**: **Proposed (auto)** one optional key `metadata.former_skill_dir` (`.pi/skills` for Pi, `.opencode/skills` for OpenCode) that the leftover rule reads, so Go names no engine directory. Reason: TRD D24, spec S2.
- **Expected skill set (S1, D2)**: compared as a set with no duplicates, not in order; the fixed-name links are read from the template's `{{methodology}}` and `{{adapter:<slot>}}` slots in `.gabo/skills/gabo-agent-templates/`, each written `gabo-<slot>` (`_` as `-`), and the adapter's frontmatter `name` is accepted in place of a link name. Reason: spec S1 says "each once" and names no order.
- **Version bump**: not in this plan, on the coordinator's instruction of 2026-11-06; see Open questions 1.
