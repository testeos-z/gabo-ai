Mode is `auto`. Owner's standing rule (2026-11-11): the agent applies its recommended answer to every open question and records it as a decision; only merging to main, tags and secrets stay the owner's. Each decision below is marked **Recorded decision (resolver: agent, rule of the owner)** and is saved through the `memory` slot. The source is the owner's approval of this intent on 2026-11-11 ("si" to creating an intent for each pending idea) and the owner's instruction "ok, completa los spec que faltan".

Evidence base (checked 2026-11-11 on `origin/dev` at `0fd848e`, and the cited pages):

- **The idea.** Anthropic, Harness design for long-running apps (https://www.anthropic.com/engineering/harness-design-long-running-apps), section "Iterating on the harness": "every component in a harness encodes an assumption about what the model can't do on its own", and "those assumptions are worth stress testing, both because they may be incorrect" and "because they can quickly go stale as models improve." The same section: "when a new model lands, it is generally good practice to re-examine a harness, stripping away pieces that are no longer load-bearing."
- **What the PRD measures today.** `docs/product/PRD.md` section 11, Success metrics: interactions per wave and their reasons ("not a reduction target"), the share of waves closed without human steps, questions recorded and resolved, plan adjustments per wave, and time from install to the first wave. Its Targets paragraph: "The first release measures without targets. After 3 to 5 real waves the baseline is known and the owner sets targets." PRD R29: every wave produces a report with interactions and reasons, decisions, questions with resolver and cleanup leftovers.
- **What a wave records today.** `.gabo/skills/gabo-cycle/SKILL.md` (Trace, D17): after every state change the cycle appends the task's status, PR, last verdict, fix rounds and open questions to `gabo/trace/<wave>`. `.gabo/skills/gabo-wave-report/SKILL.md`: ten sections, among them tasks with fix rounds (2), interactions (4) and plan-change proposals (8); the start time is in the trace. Nothing records tokens, wall time to the report's end, the number of agent sessions started, or a count of traceability gaps.
- **The measurement protocol that exists.** Accepted spec 0015, S9 (PR #475, branch `docs/intent-0015-one-subagent-layer-on-every-engine`): probe P1 runs the same intent on the nested and the flat graph and "records total tokens as the engine reports them, wall time from wave start to wave report, fix rounds per task, the number of agent sessions started, and each task's outcome"; "No threshold is set". The protocol is written on task T1 ([#476](https://github.com/testeos-z/gabo-ai/issues/476)) before the run, and T12 ([#487](https://github.com/testeos-z/gabo-ai/issues/487)) runs the flat side.
- **A way to run a role as a generic agent.** The assistant's Decision Gates table sends migrations and design norms to "generic subagent loading `gabo-db-master` or `gabo-frontend`" (`.gabo/skills/gabo-assistant/SKILL.md`): an agent can load a role's skill without a neutral-spec agent of its own.
- **The directiva check.** `gabo-pm`'s traceability check (TRD D19, `.gabo/skills/gabo-pm/SKILL.md`) lists gaps by id, and each directiva return reports "traceability gaps (or none)".
- **What the engines let an agent read about tokens.** Claude Code: the Session block of `/usage` shows token usage for the session, resetting on `/clear`; its subagent totals are not whole-run totals (the documentation lists `totalTokens` and `usage` of an Agent tool result as the subagent's final request, per the Claude Code hooks reference as read through a documentation search on 2026-11-11, to be confirmed by the probe); [OpenTelemetry export](https://code.claude.com/docs/en/monitoring-usage.md) streams token and cost metrics ([costs](https://code.claude.com/docs/en/costs), fetched 2026-11-11). Nothing in what was read lets an agent running a wave read a whole-wave total from inside the session. Codex, OpenCode and Pi were not verified for this spec.

## 2. Design

Affected files: the `gabo-cycle` and `gabo-wave-report` skills (S1), the `gabo-assistant` skill (S2, S5, S6), the memory adapter's record table (the planning topic), TRD 9.2, PRD section 11, and the catalog copies. No Go production file.

| id | decision | options considered | choice | consequences |
|---|---|---|---|---|
| D1 | What this intent does | (a) measure, and trial the merge only on the owner's approval; (b) merge pm and dev-lead now; (c) measure nothing and decide by opinion | **Recorded decision (resolver: agent, rule of the owner):** (a), the assistant's recommendation. Reason: the harness article says each component encodes an assumption to stress test one at a time, and nothing records today what a role costs or prevents. | The roles stay as they are; their fate is the owner's, decided from data. |
| D2 | Which protocol | (a) reuse 0015 S9 (five measures, a disposable repository, no threshold); (b) define a second protocol | **Recorded decision (resolver: agent, rule of the owner):** (a), as the owner's instruction. Reason: two protocols would produce numbers that cannot be compared. | The plan lists `0015/T1` and `0015/T12` as blockers (S3). PRs and plan-change proposals are the two measures this intent adds. |
| D3 | Where measures are stored | (a) a `Measures` section in the wave report, saved as the last entry of `gabo/trace/<wave>`, and a planning topic `gabo/trace/<I####>/planning`, both through `save wave trace`; (b) a new memory record kind and operation; (c) a file in the repository | **Recorded decision (resolver: agent, rule of the owner):** (a). Reason: the trace is already shared, read back and used to resume, so a section costs no new operation; a repository file would carry run data into the history. | The memory adapter's record table gains one topic. The `gabo-memory` contract's headings stay (S7). |
| D4 | How tokens are recorded | (a) as the engine reports them, with their source, else `unknown`; (b) sum the subagents' own figures; (c) estimate | **Recorded decision (resolver: agent, rule of the owner):** (a). Reason: the Claude Code documentation says a subagent's figure is not a whole-run total, and an estimate would look like a measurement; `unknown` with its source is honest. | The tokens line may stay `unknown` on engines where no total is readable; the probe records what each engine really reports (S9). |
| D5 | How the merged-role trial runs | (a) one generic agent that loads both skills, on an intent the owner names, only after approval; (b) change `agents.yaml` to merge the two agents; (c) run it without approval | **Recorded decision (resolver: agent, rule of the owner):** (a), the assistant's recommendation. Reason: the Decision Gates table already runs a role as a generic agent, so the trial needs no spec change and leaves nothing to undo. | Which intent is trialled is named at approval time; none is chosen now. |
| D6 | The rule for keeping a role | (a) compare the merged run with the baseline on fix rounds, traceability gaps and plan-change proposals, and keep the role if the merged run is worse on any; (b) a numeric target per measure; (c) decide on cost alone | **Recorded decision (resolver: agent, rule of the owner):** (a), the assistant's recommendation, with Assumption A1. Reason: these three measure whether work stays correct and traceable, which cost alone does not, and PRD section 11 says the owner sets targets only after a baseline exists. | The final call stays the owner's (S6). Assumption A1 below. |

**Assumption A1 (set by the owner, not by this spec).** "Worse" is read as: the merged run's value is higher than every value of the baseline runs on that measure. The spec invents no numeric threshold; when 3 to 5 real waves have recorded a baseline (PRD section 11), the owner may replace this reading with a target.
