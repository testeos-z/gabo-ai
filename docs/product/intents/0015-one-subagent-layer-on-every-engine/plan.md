## Steps

1. Probe P1, old graph: the protocol and the nested run on gabo 0.2.10, recorded on the issue (T1). Delivers S9 (first half).
2. `gabo check` stops requiring OpenCode's `experimental.subagent_depth` (T2); then `gabo init` stops writing it and the user docs say so (T3). Delivers S8, D6; `gabo check` update.
3. The main session runs the wave: `gabo-assistant` loads the `gabo-cycle` skill and launches every coder, with one path for every engine; what a wave does is unchanged (T4). Delivers S1, S4, S5, D1.
4. A coder validates its review request and runs the user-level reviewer script through its shell, on every engine; the step lives in the `gabo-coder` template (T5). Delivers S3, S4, D2, D5.
5. The neutral agent spec lists six agents, all launched by the main session, none with `subagents`; `gabo-cycle` and `gabo-wave-report` join `main_session.skills` (T6). Delivers S2, D3, D7.
6. The runtime skills build the six agents, grant no launch tool, link the main-session skills and remove the former agent files: Claude Code and the builder (T7), OpenCode (T8), Codex and Pi (T9). Delivers S6, S8 (skill), D4.
7. `gabo check` update (TRD 8.5): the former-agent line, the reviewer link `why:` and the main-session links (T10), after the depth rule left in T2. Delivers S7.
8. The team diagrams draw one layer, in a PR that touches only `docs/product` (T11). Delivers S10.
9. `gabo-runtime-opencode` and its stage-gate plugin follow OpenCode 2.2.6, so P5 OpenCode can run (T17, plan decision PD12). Delivers S6, S9.
10. Probes P1 (flat run) to P5 and the upgrade proof on the disposable repository; results in this plan, the TRD transitional paragraph removed (T12). Delivers S9, S5 (P4), S11.
11. On OpenCode the coder works in its worktree through `shell` `workdir` and absolute paths, never `opencode.session_move` (T18, plan decision PD13). Delivers S6.
12. gabo-ai's own catalog copy and Claude Code agents are rebuilt on one layer (T13), after T18. Delivers S6, S11.
