Owner's request, 2026-11-11, verbatim: "tenemos un modelo de sub agentes anidado donde cycle invoca coder o dev-lead quiero saber si asi es y si asi lo plantea antropic"; "ok, si queremnos cumpli mas a raja tabla todo y disminuir la sobre ingenieria que debemos hacer ?"; "que agentes conservariamos y como seria el grafo ahora ?"; and, after seeing the graph below, "perfecto, podemos crear los issues y sub issues apra este intent ?".

The graph the owner saw and approved (the target of this spec):

```text
gabo-assistant  (main session; runs the gabo-cycle skill itself)
├── gabo-pm
├── gabo-dev-lead
├── gabo-db-master        on demand
├── gabo-frontend         on demand
├── gabo-plan-reviewer    only on a plan change
└── gabo-coder × N        one per task, in its worktree
      └─ bash → user-level reviewer script (separate process, clean clone)
```

Evidence base (checked 2026-11-11 on `dev` at 0fd848e, gabo 0.2.10):

- **Today's chain.** `apps/cli/internal/skills/gabo-agent-templates/agents.yaml` lists eight spec agents plus the main-session entry (nine): `gabo-cycle` (`launched_by: main-session`, capability `subagents`), `gabo-coder` (`launched_by: gabo-cycle`, capability `subagents`), `gabo-reviewer` (`launched_by: gabo-coder`, tools `[shell]`, no skills). The coder template says "The only agent you launch is `gabo-reviewer`"; the reviewer template is five steps: validate the request, run one `bash "{{reviewer_script}}" head <n> <sha>`, take the last `VERDICT ` line, rerun once on `verdict=retry`, reply with that line.
- **The flat path already ships.** On a Pi main session `gabo-assistant` loads the `gabo-cycle` skill itself and each coder is one first-level `subagent_run` (`gabo-assistant` Wave Start step 3, `gabo-cycle` Activation Contract; intent 0013 S18, D12); the Pi coder validates the request and runs the reviewer script through `bash` (`gabo-coder` Pi exception; intent 0013 S20, D14, D15). `gabo-runtime-pi` still builds a `gabo-cycle` and a `gabo-reviewer` agent that nothing launches ("Build the `gabo-cycle` agent anyway, like every spec entry").
- **Engine limits.** Claude Code: "By default, a subagent can spawn subagents of its own, up to three layers below the main conversation"; "Set `1` to turn nesting off" (https://code.claude.com/docs/en/sub-agents.md); `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`: "In v2.1.217 through v2.1.218, the default was 1, so a subagent couldn't spawn its own unless you raised the limit; v2.1.219 raised the default to 3" (https://code.claude.com/docs/en/env-vars). OpenCode: "Nested subagents stop at `experimental.subagent_depth`, default 1" (`gabo-runtime-opencode`, source table, OpenCode 2.0.32 binary), so `gabo init` makes it at least 3 (TRD 9.4, intent 0010 S8). gentle-pi: a subagent gets no `subagent_*` tools (intent 0013 S18).
- **TRD.** D1: "Native subagents; Orca only for the reviewer and direct sessions", consequence "Nesting depth limited to 3 below the assistant"; section 2 "Nesting depth. At most 3 below the assistant"; section 12 lists the nesting-depth limit as a risk; D20: "The generated reviewer agent only validates the request (PR number, 40-hex SHA) and invokes the script, then relays the `VERDICT` line".
- **Anthropic guidance.** "Handing the same task to a subagent doesn't make the answer any better. A fresh reviewer does help, because it hasn't seen your reasoning, which is a different thing from delegating." (https://code.claude.com/docs/en/best-practices); "you should consider adding complexity only when it demonstrably improves outcomes" (https://www.anthropic.com/research/building-effective-agents). The fresh reviewer gabo keeps is the reviewer script's own agent review in a clean clone (R9, R22) and the clean-context plan reviewer (D8), not the relay.

Known cost, stated plainly: the main session carries the wave's context (every coder outcome, each tracker and ledger write) that the `gabo-cycle` subagent held before. It is bounded because the wave's state lives in the tracker, the ledger and the trace, not in the conversation: the session can compact, or be closed and resumed by the holder from the trace (TRD D17), without losing the wave. Lower token use and latency are expected from two fewer agent sessions per wave and per review round, but they are **not measured**; S9 measures them and this spec promises no number.

Out of scope, each a separate later intent: a spend or turn cap for auto mode; moving traceability back to deterministic checks; a reviewer severity filter; delegation by reason; measuring roles. Also out: merging `gabo-pm` and `gabo-dev-lead`; starting coders as separate processes through `agent_host`.

## 2. Design

One path replaces two. The main session becomes the wave runner by loading the skill the `gabo-cycle` agent loaded; the coder takes over the relay's two mechanical steps; nothing else moves. The reviewer scripts, the slot contracts, `gabo.yaml` and the tracker, ledger and trace formats are untouched.

Before and after:

```text
before (0.2.10; Pi excepted)                 after (every engine)
assistant                                    assistant  (runs the gabo-cycle skill)
└─ gabo-cycle            layer 1             └─ gabo-coder × N        layer 1
   └─ gabo-coder × N     layer 2                └─ bash → reviewer script (process)
      └─ gabo-reviewer   layer 3
         └─ bash → reviewer script (process)
```
