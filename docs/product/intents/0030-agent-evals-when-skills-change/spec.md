## 0. Terms and evidence

Terms used below:

- **Agent configuration:** a `gabo-*` skill, an agent definition, the methodology adapter, the instruction file, or a hook of intent 0028.
- **Instruction file:** the file an engine reads at session start. The intent and the playbook call it CLAUDE.md. This repository has `AGENTS.md` (26 lines) and no `CLAUDE.md` at its root; both names are human-only paths (`gabo.yaml:53`). Which file receives the blocks is question 3.
- **Eval task:** one finished piece of gabo work replayed as a fixed task with its accepted outcome. **Set:** the accepted eval tasks. **Run:** one execution of the set. **Baseline:** the run the owner accepted as the reference.
- **Notice:** the comment gabo posts on a pull request when a run falls below the owner's threshold.

Evidence, checked 2026-11-13 on this branch:

- **Nothing measures agent behavior today.** `apps/cli/internal/skills/` holds 34 `gabo-*` folders. Its tests check the text of the skills, not what an agent does with them: for example `TestCoderRunsTheReviewerScriptOnEveryEngine` (`coder_test.go:42`), `TestCoderDecisionGateRowsKeepTheirText` (`coder_test.go:109`) and `TestWaveReportHasMeasuresSection` (`measures_test.go:10`). Intent 0022 measures a wave (wall time, fix rounds, sessions, tokens as reported), not the behavior of an agent on a fixed task.
- **The instruction file has none of the three blocks.** `AGENTS.md` has the sections Stack, Layout and Conventions; it lists no command, no healthy output and no repeated mistakes.
- **The cap rule exists.** Spec 0020 (accepted 2026-11-12) caps coder turns, coders launched and fix rounds, pauses and asks the owner at a cap (its S4), states per engine whether a cap is enforced or advisory (its S7), and caps no spend (its D1: no engine lets gabo cap spend from inside a wave).
- **The automatic merge and its existing stop.** `gabo.yaml:52` sets `review.auto_merge: true`. The user-level script `merge-head.sh` (outside the repository) already reads the PR comments (lines 65 to 70) and already refuses to merge a PR that touches a human-only path, posting a comment and logging `NEEDS-HUMAN-MERGE` (lines 72 to 90). `.claude/`, `AGENTS.md`, `CLAUDE.md` and `gabo.yaml` are human-only (`gabo.yaml:53`), and `.gabo/skills/` is a built-in human-only path of that script (its header, lines 12 to 13). A PR that changes only the catalog under `apps/cli/internal/skills/` is not covered by that stop.
- **The trace and the report exist.** `gabo-cycle` appends each task's status, PR, last verdict, fix rounds and open questions to `gabo/trace/<run id>` (its Trace rule and step 6); `gabo-wave-report` section 2 prints one `Tasks` line per task.

## 2. Design

The change adds one skill with scripts (the runner), a versioned set of task files with one baseline, a lessons file, three blocks in the instruction file with their template, and rules in the assistant's skill for the trigger, the incident flow and the two-times rule. It adds no CLI command. The measure reuses what exists: the coder engine, the coder's report of spec 0027, the cap rule of spec 0020 and the wave trace.

Flow of a run: the assistant sees a change to the agent configuration (S3) and starts the runner on the owner's machine with the head commit. For each accepted task the runner prepares a scratch copy of the repository at the task's starting commit with the changed configuration applied, starts the coder engine on the task input, then runs the task's outcome checks and reads the coder's report (S5). It writes the run report (S7), compares it with the baseline (S6) and, when the run is complete and below the threshold, posts the notice on the PR (S9). Assumption of gabo-pm: a task run writes nothing outside its scratch copy (no push, no PR, no tracker write), and the scratch copy is created with `mktemp -d` outside the worktree; the notice is the only write a run makes to the repository host.

Affected files (final paths are the plan's): the new runner skill under `apps/cli/internal/skills/` and its copy under `.gabo/skills/`; the set and its baseline; the lessons file; `gabo-assistant` (trigger, incident and two-times rules); `gabo-cycle` and `gabo-wave-report` for the incident line of the trace; `gabo-setup` and the template (S19); the instruction file (human merge); `gabo.yaml`, its loader and both schema copies for the configuration values (human merge); the merge step of the reviewer for S10 (question 1).

Every decision below is **Proposed (auto)** unless it names an owner decision; the owner's acceptance of this spec confirms or changes each.
