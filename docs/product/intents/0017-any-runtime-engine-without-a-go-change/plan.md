The spec was accepted by the owner on 2026-11-11 (spec section 7), verbatim: "si a los 2", with its decisions D1 to D4 and open questions 2 to 5 as proposed (resolver: agent, rule of the owner). `gabo.yaml` mode is `auto`: every fixed question below is answered by `gabo-dev-lead`, marked **Proposed (auto)** with a one-line reason, for one-pass approval. The questions the spec left open are recorded under Plan decisions (resolver: agent, owner's rule of 2026-11-07, verbatim: "from now on, for open questions, take your own recommended answer instead of waiting for the owner. Record each one as a decision (what, question, choice, reason, wave, task, resolver: agent) and list them in your next report.").

What the code already does (read 2026-11-11 on `dev`): `engineconfig.Set` keeps any other engine name after the four, `initcmd` already prints the flexible-tier line `<engine>: flexible tier: skills and configuration only; nothing written` (`engineconfig/engines.go` line 133), and `gabo check` already reports `✗ runtime <rt> has no runtime skill gabo-runtime-<rt>` (`check/usecase.go` line 340) and keeps flexible-tier warnings (`agentmeta.go`, `mainsession.go`). What stops a builder engine is the config layer: the `runtimes` list and `engineChoice` in `config/config.go` and the `enum` of `$defs/engine` and `$defs/runtime` in both schema copies. So the Go change is the config validation and the schema; the rest is proof.
