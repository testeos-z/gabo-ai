It refuses a relative directory, a directory inside the project, a symlink and a path that is not a directory. `Init.Run` runs it on every run before the catalog, so its lines come first. Nothing compares the content.
- **T14's mechanism, merged.** `apps/cli/internal/slices/initcmd/usecase.go`: the constant `HashFile = ".gabo/CATALOG_HASH"` next to the stamp `.gabo/VERSION`; `contentHash`, a sha256 over the files sorted by path (length-prefixed path, length-prefixed data); `sameContent`, which reads the stamped hash and treats a missing hash as different; `copyCatalog` writes the hash before the stamp. With the stamp equal to the binary version and a different or missing hash it refreshes the copy and prints `catalog refreshed <version>: content differs from the embedded catalog` then `next: ask your agent to rebuild the agents, then run gabo check`; with an equal hash it prints `catalog is current (<version>); nothing changed`. ## 2. Design

Affected components: `apps/cli/internal/engineconfig` (`piRule` in `pi.go`), `apps/cli/internal/slices/initcmd` (`reviewer.go` and the digest function of `usecase.go`) with their tests and golden files, and `docs/product/TRD.md` 9.4 (S5). No new config key, no change to `gabo check`, and no new file in the repository: the reviewer hash lives in the user copy.

| id | decision | options considered | choice | consequences |
|---|---|---|---|---|
| D1 | When and how the Pi refusal is decided | (a) run the package check (read-only `pi list`, then `gentle-shell` on `PATH`) before the Pi lines are built, and warn only when no package is found; (b) keep the warning and add a note when a package exists | **Proposed (auto):** (a). Reason: the issue asks to check before warning, and a note would still show the refusal. The rule is the one `gabo-runtime-pi` step 2 already uses, so the two stay the same. | `pi list` runs once per `gabo init` with `pi` in `runtimes.*`. A missing `pi`, or a `pi list` that fails or times out, counts as no package (S2). |
| D2 | How the user-level reviewer's content is compared | (a) reuse T14's approach: a stamped content hash next to the version stamp, the same digest function and the same rule that a missing hash counts as different; (b) compare the installed tree with the embedded files one by one on every run; (c) define a second digest for the reviewer | (a), by the instruction to reuse T14's mechanism and not to duplicate or redefine it (owner: "no me gusta tener nada duplicado"). **Proposed (auto):** the file name `REVIEWER_HASH` and its place inside the user copy next to `VERSION`, parallel to `.gabo/CATALOG_HASH` next to `.gabo/VERSION`; the line wording parallels T14's `catalog refreshed <version>: content differs from the embedded catalog`. Reason: it needs no new format, and a hash stamped at install cannot be fooled by a stale file that is still on disk. | The plan moves T14's digest function to one helper used by the catalog and the reviewer; it does not copy it. A reviewer copy installed before this change has no `REVIEWER_HASH`, so it is refreshed once at the next `gabo init`, as T14 does for a catalog without a hash. The plan confirms that nothing that reads the reviewer folder (the runtime skills' links, the reviewer scripts) is affected by one more file in it. |
