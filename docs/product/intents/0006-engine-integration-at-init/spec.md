## 2. Design

**Evidence (checked 2026-11-04).**

- Claude Code, project scope: "To cover one repository's contributors instead of your whole fleet, set `extraKnownMarketplaces` and `enabledPlugins` in that repository's `.claude/settings.json`. The `extraKnownMarketplaces` entries apply only in a folder the contributor has trusted." A plugin "that the marketplace lists by a relative path loads from the marketplace copy once the repository's `extraKnownMarketplaces` entries apply"; a plugin with an external source would also need `claude plugin install <name>@<marketplace> --scope project`. Marketplace entries are keyed by the marketplace `name`, with `"source": { "source": "github", "repo": "<owner>/<repo>" }`; plugins are keyed `plugin-name@marketplace-name`. Source: https://code.claude.com/docs/en/plugins/org (sections "Require a marketplace and its plugins", "Require plugins per repository"); both keys allowed in "Any file": https://code.claude.com/docs/en/settings-reference. The gabo-ai marketplace is `gabo-ai` and lists plugin `gabo` by the relative path `./plugins/claude-code` (`.claude-plugin/marketplace.json`), so no install command is needed after trust.
- Codex, project scope: "The repo marketplace at `.agents/plugins/marketplace.json` makes plugins discoverable. Use the repo's `.codex/config.toml` to control whether a local-marketplace plugin is enabled for that project: `[plugins."my-plugin@local-repo"] enabled = true`." and "Codex loads project `.codex/config.toml` only for trusted projects. Project settings override user, cloud-managed, and system defaults." Source: https://developers.openai.com/codex/plugins/build (section "Enable or disable a plugin for a repo"). The configuration reference adds `marketplaces.<name>.source_type` (`git | local`), `marketplaces.<name>.source`, `.ref`, `.sparse_paths`: "Marketplaces can be defined in system, cloud-managed, user, or trusted-project config.toml", and `plugins.<plugin>.enabled`: "trusted-project settings can override user, cloud-managed, and system defaults. Marketplace refresh can install or refresh configured plugins even when disabled." Source: https://developers.openai.com/codex/config-file/config-reference. Not stated in either page: whether a project-declared Git marketplace plus `enabled = true` installs the plugin with no `codex plugin add`. That is D4 and S12.
- gabo-ai publishes the Codex marketplace `gabo-ai` at `.agents/plugins/marketplace.json` with plugin `gabo` at `./plugins/codex`, policy `AVAILABLE`; the README installs it with `codex plugin marketplace add testeos-z/gabo-ai` and `codex plugin add gabo@gabo-ai`, and Codex runs plugin hooks only after the user trusts them in `/hooks`.
- `@testeos-z/gabo-pi` returned HTTP 404 from `https://registry.npmjs.org/@testeos-z%2fgabo-pi` on 2026-11-04 (not published). The README installs it from a checkout with `pi install /path/to/gabo-ai/packages/pi`.
- `gabo-runtime-opencode` writes `.opencode/plugins/gabo-stage-gate.js` and the project-level `experimental.subagent_depth` key on every build (`apps/cli/internal/skills/gabo-runtime-opencode/SKILL.md`, commit 385e706).
- `initcmd` today reads only the existence of `gabo.yaml` and writes only `.gabo/skills/`, `.gabo/VERSION` and the user-level reviewer skill (`apps/cli/internal/slices/initcmd/usecase.go`, `reviewer.go`); `go.mod` has `gopkg.in/yaml.v3` and no TOML library.

**Shape.** One new domain unit in the `initcmd` slice, a pure function from (engine set, current bytes of each engine file or "missing", binary version, flags) to (new bytes per file or "no change", report lines, failure flag). The use case reads `gabo.yaml` and the engine files through the existing `Store` port (plus a read of the file kind through `Lstat`), calls the function, writes only changed files and appends the report. `gabo check` gets one read-only rule that calls the same key table (S11). No new command, no flag (PRD R31).
