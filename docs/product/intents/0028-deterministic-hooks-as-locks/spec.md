## 2. Design

Every rule lives in gabo's Go `check` slice. Two hook modes exist after this change: `--pre-write` (file tool calls: stage gate, `human_only_paths`, `test_files`) and `--pre-command` (shell tool calls: `shell_guard`, `release_gate`). Each engine keeps one thin relay per tool kind; the relay sends the tool-call JSON and maps gabo's exit code to the engine's allow, deny or ask answer. `credentials` is enforced by each engine's own permission rules, written by `gabo init` (D5). On each call gabo reads `gabo.yaml` from the project root: `mode`, the lock switches and `review.human_only_paths`.

Flow of one call: engine event, relay, `gabo check --pre-<kind>` with the JSON on stdin, gabo matches the rules of the locks that are not `off`, takes the strictest outcome (`block` over `ask` over `warn`), prints the message and exits; the relay applies it. Session kind (coder or other agent session, decision 13) comes from the agent or session id that S1 (b) probes; where an engine gives none, every session is judged with the coder rules (assumption, the stricter reading).
