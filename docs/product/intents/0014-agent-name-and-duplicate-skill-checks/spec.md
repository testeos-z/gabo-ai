Owner's decisions (scope), 2026-11-07:

- Rule 1, verbatim, answering whether `gabo check` should fail when a Claude Code or Codex agent file declares no `name`: "que falle".
- Rule 2, verbatim, accepting the proposal that a skill listed twice gets its own failure line ("listed twice") instead of "not in the agent spec": "si no la listo tomare tu propuesta para toda opcion no listada".

Evidence base (checked 2026-11-07 on `dev` at 1e4de04, gabo 0.2.10):

- **Name rule today.** `apps/cli/internal/slices/check/agentname.go` `checkAgentName` fails only `name != "" && name != id` with `✗ agent <id> (<runtime>): declares name <name>`; its comment says "a file that declares no name is not a declared name". It returns early when the runtime skill declares no `metadata.agent_name`, or when the engine is flexible tier and declares no `metadata.agent_skills` (intent 0008 S2). `usecase.go` calls it for each file of each spec agent id, not for the main-session agent file `gabo-assistant` (only `checkAgentEngine` runs for that one). `agentmeta.go` `agentPlace.name` returns the trimmed string at the declared place, else `""` (absent key, non-string value, unparsable frontmatter or TOML).
- **Engines in scope.** `metadata.agent_name` is declared by `gabo-runtime-claude` (`frontmatter:name`), `gabo-runtime-codex` (`toml:name`) and `gabo-runtime-pi` (`frontmatter:name`); `gabo-runtime-opencode` declares none (OpenCode names an agent by its file name). `gabo-runtime-builder` tells a flexible-tier runtime skill to declare it "omit it when the engine names an agent by its file name".
- **The engines need the name.** Codex: `codex-rs/agent-roles/src/agent_role_config.rs` rejects a role file with "agent role file at {} must define a non-empty `name`" (checked on `openai/codex` `main`), and the loader only logs a startup warning. Claude Code: the subagent frontmatter table marks `name` required, and a project agent file without it "is skipped silently" (https://code.claude.com/docs/en/sub-agents, checked 2026-11-07).
- **Duplicate rule today.** `agentskills.go` `compareSkills` matches the listed skills against the wanted set; a listed skill that matches no still-unmatched wanted entry is `extra`, so the second copy of a spec skill is extra and prints `✗ agent <id> (<runtime>): skill <name> not in the agent spec`. A wanted fixed-name link also matches its adapter's frontmatter `name` (`alt`), so `gabo-memory` plus `gabo-memory-engram` in one list is reported the same way today. `agentskills_test.go` case "duplicate" pins that line; golden `testdata/golden/agent-skills-extra.golden` pins a real extra skill.
- **Docs that state the rules.** `check/command.go` help text ("a file that declares none passes"), `docs/compatibility.md` (Per-agent checks), TRD 9.4 (Per-agent skills, Declared agent names), PRD R33 (intent 0008 amendment).

## 2. Design

Two rules in `slices/check`, both inside the existing per-agent loop of `usecase.go`; no new metadata key, no change to the runtime skills, the templates or `gabo init`. Agent files built by the current runtime skills already declare a name and list each skill once, so a correct build prints nothing new.

| id | decision | options considered | choice | consequences |
|---|---|---|---|---|
| D1 | Rule 1 outcome | A: fail / B: warn / C: no line (today) | A, decided by the owner, verbatim: "que falle". | S1; existing projects with a nameless agent file now exit 1 until rebuilt. |
| D2 | What counts as "declares no name" | A: any empty result of `agentPlace.name` (absent, blank, non-string, unparsable file) / B: only an absent key | A, accepted with the spec (2026-11-07): Codex needs a non-empty `name`, Claude Code skips a file without one, and an unparsable file loads under neither engine; B would let `name = ""` pass. | One rule over the existing `agentPlace.name`; no new parser. |
| D3 | Rule 2 outcome | A: own `listed twice` line / B: keep `not in the agent spec` | A, decided by the owner (proposal accepted, verbatim: "si no la listo tomare tu propuesta para toda opcion no listada"). | `compareSkills` returns duplicates apart from extras. |
| D4 | Next step of the new lines | A: the existing rebuild step for both / B: a new `next: remove the second <name> from <file>` for `listed twice` | A, accepted with the spec (2026-11-07): agent files are built, not hand-edited (TRD 9.4 rebuild hint); a rebuild lists each skill once and writes the name, and the `✗` line already says what is wrong. B adds a new next-line text to keep in sync with the docs. | No new `next:` text; the per-agent group keeps one next step. |
| D5 | Several copies of one skill | A: one `listed twice` line per name / B: one line per extra copy | A, accepted with the spec (2026-11-07): the fix is the same for two or three copies (keep one), and one line per name keeps the output short. | S2. |
| D6 | Line order inside one agent file | A: `missing`, `listed twice`, `not in the agent spec` / B: interleaved in list order | A, accepted with the spec (2026-11-07): it keeps today's order (missing before extra) and puts the new group between them, so existing output of files without duplicates is unchanged. | S2, S3. |
