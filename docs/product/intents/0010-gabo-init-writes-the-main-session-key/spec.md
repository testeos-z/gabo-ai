Evidence base (checked 2026-11-06 on `dev` at 8eacf4e, gabo 0.2.8):

- **`gabo init` writes the integration keys only.** `apps/cli/internal/engineconfig/claude.go` `claudeKeys` holds `extraKnownMarketplaces."gabo-ai"` and `enabledPlugins."gabo@gabo-ai"`; `claudeRule` inserts a missing key, keeps and reports a key with another value (`kept .claude/settings.json <key>: <value> (your setting; gabo leaves it)`), and on invalid JSON or a non-object top level writes nothing and prints one `✗ .claude/settings.json: <reason>; fix it and run gabo init again` line. The engine `Rule` gets only the files and the version (`engineconfig.Input`), not `runtimes.assistant`. `engineconfig/opencode.go` `opencodeRule` writes nothing and only reports the stage-gate plugin (intent 0006 S6).
- **The runtime skills write the other engine keys.** `gabo-runtime-claude` Main-Session Entry step 3 merges `agent: "gabo-assistant"` into `.claude/settings.json`, and the same section removes it when `runtimes.assistant` is not `claude`. `gabo-runtime-opencode` Prerequisites steps 2 to 4 write `experimental.subagent_depth` into the first existing of `opencode.json`, `opencode.jsonc`, `.opencode/opencode.json`, `.opencode/opencode.jsonc` (else a new `.opencode/opencode.json`), and build step 9 merges or removes `default_agent: "gabo-assistant"` there. Every runtime skill (`gabo-runtime-claude`, `-codex`, `-opencode`, `-pi`) also removes the other engines' main-session keys. `gabo-runtime-builder` step 6 has a builder-written runtime skill merge its own key for `kind: agent`.
- **The check loops.** `apps/cli/internal/slices/check/mainsession.go` `checkAssistantEntry` reports the config-file piece of a `kind: agent` entry as `✗ <file>: gabo assistant entry missing|incomplete for <engine>`, and `checkStaleEntries` reports a leftover key as `✗ <file>: gabo assistant entry for <engine>, but runtimes.assistant is <value>`; every one of these lines carries `NextRebuild` (`next: ask your agent to rebuild the agents, then rerun gabo check`). A key that holds another value counts as absent. `check/opencode.go` reports a low or missing `experimental.subagent_depth` with `next: set experimental.subagent_depth to 3 in <file>, then rerun gabo check`.
- **The vulcam report** (cappy-lab/vulcam PRs #650 and #652): in a project whose hooks stop agents from writing Claude settings, the rebuild cannot write `agent`, so `gabo check` keeps reporting `gabo assistant entry incomplete for claude` with the rebuild hint, and the owner adds the key by hand.
- `metadata.main_session` of `gabo-runtime-claude` declares `kind: agent`, `config: [.claude/settings.json]`, `key: agent`; of `gabo-runtime-opencode`, `kind: agent`, the four OpenCode config files above and `key: default_agent`. `gabo-runtime-codex` and `gabo-runtime-pi` declare `kind: block` (the scoped block in `AGENTS.override.md`, `AGENTS.md`, and for Pi `CLAUDE.md`).
- This repository's `.claude/settings.json` on `dev` holds the two integration keys and no `agent` key; `.claude/` is a `review.human_only_paths` entry.

## 2. Design

`gabo init` already owns a pure engine table in Go (intent 0006 D2, TRD D24 as amended); the main-session keys and the OpenCode depth key join it, and the rule gets `runtimes.assistant` as input. The runtime skills keep what is runtime knowledge an agent must build: agent files, links, the stage-gate plugin and the Codex and Pi scoped block.

| id | decision | options considered | choice | consequences |
|---|---|---|---|---|
| D1 | Where `gabo init` takes the keys from | A: the Go `engineconfig` table / B: read `metadata.main_session` of the runtime skill in the catalog copy at run time | A, **Proposed (auto)**: the integration keys already live in that table (intent 0006 D2) and the depth key is not in any metadata; S7 keeps the table and the metadata in step. | `engineconfig.Input` gains the assistant engine; a new OpenCode rule writes JSONC. |
| D2 | When `gabo init` removes the gabo value | A: only for engines still in `runtimes.*` / B: for every full-tier engine file that holds exactly `gabo-assistant`, whatever `runtimes.*` says | B, **Proposed (auto)**: `gabo check` reports a stale entry of any full-tier engine (TRD 9.4), so A would leave a failure `gabo init` cannot clear. | `gabo init` may edit `.claude/settings.json` or an OpenCode config of an engine no longer declared, only to delete that one member. |
| D3 | The Codex and Pi scoped block | A: stays with the runtime skills / B: `gabo init` writes it too | **A, decided 2026-11-06**: presented to the owner with this proposal and reasoning, the owner did not object and, in the same instruction ("el agente en la nube puede aprobar sus PR a dev quiero el PR de 11 y 10 de dev a main"), had the coordinator apply proposed answer A. Reason: the owner's scope names engine config keys only, and the block is an instructions file built from the catalog template like an agent file. Known cost: a project whose hooks stop agents from writing `AGENTS.md` would still loop on the block; B (a `gabo init` block writer) would come as a later intent. | With A, Codex and Pi keep the 0009 rebuild path and hint; with B, `gabo init` also owns the block and S6 extends to the block piece. |
| D4 | A flexible-tier engine's main-session key | A: the builder-written runtime skill keeps writing its own key, the one exception / B: `gabo init` writes it from that skill's `metadata.main_session`, engine-neutral | **A, decided by the owner on 2026-11-06** ("tomare su propuesta"). Reason: `gabo init` writes nothing engine-specific for a flexible-tier engine (PRD R32, TRD D28), and B widens that recorded decision. Known cost: A keeps a second writer of engine config, against the owner's "gabo init is the single writer of engine config". | With A, `gabo-runtime-builder` step 6 keeps its key write for `kind: agent` and the S6 `gabo init` hint applies to full-tier engines only; with B, PRD R32 and TRD D28 are amended. |
| D5 | `experimental.subagent_depth` | A: stays with `gabo-runtime-opencode` / B: moves to `gabo init` with the "at least 3" rule | B, decided by the owner's scope, verbatim: "runtime skills stop writing engine config keys and only build agent files and links". The raise-to-3 rule is kept as the runtime skill applies it today, **Proposed (auto)**: a lower value breaks the assistant → cycle → coder → test runner chain (TRD 2). | `gabo init` writes an OpenCode file for the first time (amends intent 0006 S6). |
| D6 | `gabo init` writes the key before the agent file exists | A: write it on every run / B: write it only when the agent file exists | A, **Proposed (auto)**: one command completes setup, and the order of `gabo init` and the rebuild must not matter. Assumption the plan verifies with one probe per engine before the code task: Claude Code and OpenCode start normally when the default agent is not built yet. If a probe fails, the plan returns a plan-change proposal. | The report adds the build step (S8). |
| D7 | Which `gabo check` hints change | A: only the line where the key is the only gap / B: every line whose fix is `gabo init`, per piece | B, **Proposed (auto)**: each line names the step that clears it, so no hint loops (owner rationale, verbatim: "clear guidance, no loop"); when the key is the only gap this gives exactly the owner's case. | Four hints change (S6); the rebuild hint stays on the other pieces. |
